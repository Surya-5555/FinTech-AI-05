# Domain Model

## Overview
The domain layer of the Razorpay AI Revenue Recovery system is built using tactical Domain-Driven Design (DDD) principles. It is completely decoupled from the persistence layer (Prisma), the delivery layer (HTTP/NestJS), and external third-party APIs. The domain model encapsulates all state transitions, financial logic, and qualification rules.

## Core Domain Entities & Aggregates

### The RevenueCase (Aggregate Root)
The `RevenueCase` represents the lifecycle of a single failed payment or subscription. 
- It maintains the aggregate state (`OPEN`, `PLANNED`, `EXECUTING`, `RECOVERED`, `FAILED`).
- It acts as the consistency boundary. Operations like "Propose Plan" or "Execute Intervention" are invoked on the `RevenueCase` aggregate, which validates the state transition internally.
- Example: You cannot transition a `RevenueCase` to `RECOVERED` if its current state is `FAILED`. The domain aggregate strictly rejects this.

### RecoveryPlan & Interventions
A `RecoveryPlan` is a value object (or internal entity) generated by the AI evaluation phase and attached to the `RevenueCase`. An `Intervention` represents the execution attempt of that plan.
- **Deterministic Rules:** Before a `RecoveryPlan` is accepted, the domain model applies deterministic limits (e.g., `MAX_ATTEMPTS_PER_CASE = 3`, `COOLDOWN_PERIOD_MINUTES = 60`). The AI does not bypass these rules.

## Pure Domain vs. Persistence Models
We maintain a strict boundary between what the database sees and what the business logic uses.
1. **Prisma Client Models (`@prisma/client`):** These are anemic data structures used purely for database I/O.
2. **Domain Entities (`libs/domain/src`):** These are rich TypeScript classes containing behaviors (methods).
3. **Mappers (`libs/persistence/src/mappers`):** This layer translates the Prisma database models into the pure Domain Entities on read, and serializes the Domain Entities back into Prisma models on write.

This isolation ensures that if we were to swap Prisma for TypeORM or raw SQL, zero lines of business logic inside `libs/domain` would need to change.
