# CI/CD and Quality Gates

This repository uses GitHub Actions for continuous integration, quality gates, and automated evaluation evidence generation.

## Workflows

1. **CI (`ci.yml`)**: Runs linting, typechecking, tests, and builds against synthetic Postgres and Redis service containers.
2. **Evaluation (`evaluation.yml`)**: Evaluates the system using deterministic tests (`pnpm evaluate-smoke`) and generates sanitized artifacts for AI decisions.
3. **Resilience (`resilience.yml`)**: Tests the failure recovery state machine using `pnpm failure-demo`.
4. **Docker Demo (`docker.yml`)**: Verifies the Docker Compose setup works end-to-end.
5. **Security (`security.yml`)**: Scans dependencies and secrets.
6. **Dependency Review (`dependency-review.yml`)**: Reviews licenses and vulnerabilities in PRs.

## Local Equivalents

You can run the CI checks locally before pushing:
- `pnpm lint`
- `pnpm typecheck`
- `pnpm test`
- `pnpm evaluate-smoke`
- `pnpm failure-demo`
- `make verify`

## Service Containers

The GitHub Actions use isolated Docker service containers for Postgres and Redis.
They use the `TEST_DATABASE_URL` environment variable. Never configure production LLM or Razorpay keys in GitHub Actions.

## Artifact Retention

Artifacts generated by the workflows (e.g., evaluation reports, test metrics, CI summaries) are sanitized (no PII or raw secrets) and retained for 14 days.

## Continuous Deployment

For the scope of the Buildathon, continuous deployment is not configured. Reviewers and developers will pull the code and run `make demo-up` to spin up the local deterministic demo environment.
