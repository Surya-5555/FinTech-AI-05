# ADR-019: GitHub Actions Quality Gates

**Status:** Accepted
**Date:** 2026-08-22
**Context:** Phase 5.3 (GitHub Actions CI, Quality Gates, and Evidence Artifacts)

## Context and Problem Statement
We need a CI system that continuously verifies the Razorpay AI Buildathon repository. It must prove that evaluations are deterministic, code passes quality gates, and failure recoveries are safe. However, the CI environment must not have access to live production credentials (like Razorpay live keys or LLM API keys) to avoid financial risks and leaks.

## Decision
We will implement a suite of GitHub Actions workflows:
- **CI**: Standard checks (lint, typecheck, test, build).
- **Evaluation**: Runs `pnpm evaluate-smoke` for deterministic metrics.
- **Resilience**: Runs `pnpm failure-demo` to ensure idempotency and recovery state machines are intact.
- **Docker Demo**: Verifies that the local Docker Compose setup works properly.
- **Security & Dependency**: TruffleHog for secret scanning, Dependabot for updates, and `pnpm audit` for vulnerabilities.

All operations in CI will use benchmark data, simulated LLM modules, and simulated Razorpay API responses. We will use Docker service containers in GitHub Actions to provide temporary Postgres and Redis instances.

## Rationale
1. **Safety First**: By forbidding live secrets in CI, we guarantee that no accidental money movement or real user interaction can happen during automated tests.
2. **Deterministic Evidence**: Benchmark data allows us to produce consistent evaluation scores over time.
3. **Auditability**: Evidence artifacts (metrics, summaries) generated by the CI pipeline prove that the system works as intended for the Buildathon reviewers.
